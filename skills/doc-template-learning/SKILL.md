# 模板驱动写作（Template-Driven Writing）

收到模板后**先学习、后动笔**：把模板拆成可复用的「骨架 + 风格卡」，再据此完成新文书，保证新文档与模板同构、同味、同规范。

## 何时使用

- 用户传入模板全文（对话粘贴）或模板文件（.md / .docx / .txt / PDF，先 read 或可视化读取），并要求按模板完成新文书时。
- 用户说"按这个格式写"、"模仿这份文档"、"学一下它的思路"、"照它的风格来"时。
- 模板可以是文档正文，也可以是几篇同类文档（多篇时先交叉提炼共性，再写）。

## 工作流

### 1. 接收并读取模板

- 对话粘贴：直接使用。
- 文件路径：用 read 读取（.docx/.pdf 先转文本或可视化提取）；读取失败就向用户要文本。
- 多份模板：合并拆解，标注各模板共有的骨架与各自特色，取共性为主、特色为辅。

### 2. 四维拆解（核心步骤）

逐维分析，把发现**写进笔记**（可用 todo 或草稿文件，最终汇入骨架与风格卡）：

**① 结构（骨架）**：章节层级树（几级标题、每节的标题命名规律）、章节顺序与组织逻辑（总-分-总？问题→方案→验证？时间线？）、每节大致篇幅与段落节奏。

**② 思路（逻辑）**：信息编排顺序（先结论后细节，还是先铺垫后揭晓）、每节回答什么问题、论证/叙述方式（数据驱动？案例驱动？对比？）、例证与数据放在什么位置、如何做过渡。

**③ 语言（风格）**：语气（正式/中性/亲切）、人称（我们/你/无主语）、术语使用（专有名词、中英混用习惯）、句式习惯（长句/短句、主动/被动）、标点与数字规范、避免 AI 味（可调用 humanizer-zh / remove-ai-flavor / stop-slop 自查）。

**④ 格式（排版）**：标题层级与编号方式（1.1/1.1.1、一/（一））、列表/表格的使用场景、代码块标注与命令呈现方式（是否带提示符、注释语言）、加粗/斜体/引用块用法、图表与目录习惯、页眉页脚或落款等附加要素。

### 3. 产出「骨架 + 风格卡」并持久化

把拆解结果整理成两个文件，写入工作区 **`docs/style-cards/`**（不存在则创建；文件按模板主题命名，如 `docs/style-cards/使用说明书-骨架.md`、`docs/style-cards/使用说明书-风格卡.md`；同一主题多份模板则加序号）：

- **骨架文件**：章节树（含层级与标题命名）+ 每节要点（该节回答的问题、必备内容、篇幅提示）。
- **风格卡文件**：语言规范（语气/人称/术语表/句式/数字标点）、格式规范（编号/表格/代码块/强调用法）、思路特征（编排顺序/论证方式/过渡手法）、避免事项（模板中绝不出现的写法）。

写完后向用户简要报告学到的要点（一两句即可），并说明已保存的位置；用户可当场补充或修正模板意图。

### 4. 按骨架与风格卡撰写

- 先按骨架列出新文书大纲，**与用户确认后再写正文**（确认方式：直接给出大纲等用户点头，或用 ask_user_question）。
- 撰写时严格对齐：骨架（章节不缺、顺序不乱）、思路（编排逻辑与模板一致）、语言（语气/术语/句式照风格卡）、格式（编号/表格/代码块照风格卡）。
- 内容永远来自真实调研（项目代码、配置、命令），模板只提供形式与思路，**严禁把模板里的具体数据、版本号、项目名照抄进新文档**。

### 5. 对照自检（交付前必做）

逐项对照模板检查新文档：
- 结构完整：骨架每个章节都写了，层级与标题命名一致？
- 思路一致：信息编排顺序、论证方式符合模板逻辑？
- 语言一致：语气、人称、术语、句式与风格卡相符？无 AI 味？
- 格式一致：编号、表格、代码块、强调用法与模板排版相符？
- 内容真实：无照抄模板数据、无编造细节、命令可执行？
- 错别字与标点：终检一遍。

自检发现问题就地修改，然后交付并说明（可选）新文档与模板的对应关系。

## 原则

- 模板是"形式和思路的范本"，不是"内容的复制源"。
- 学习产物（骨架/风格卡）是工作区资产，本次完成后再写同类文书可直接复用，不必重新传入模板；但用户明确传了新模板时，以新模板为准重新拆解。
- 模板意图不明（章节要删/要加、语气要变）时，先问清楚再动笔，不猜。
