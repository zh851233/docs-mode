# 模板驱动写作（Template-Driven Writing）

收到模板后**先学习、后动笔**：把模板拆成可复用的「骨架 + 风格卡」，再据此完成新文书，保证新文档与模板同构、同味、同规范。**没有用户模板时，自动从模板知识库选模板，流程与质量完全一致。**

## 三层模板知识库（按优先级查找）

| 层级 | 位置 | 内容 | 何时优先 |
|---|---|---|---|
| L1 工作区确认版 | 工作区 `docs/style-cards/` | 本会话/本项目用户确认过的骨架+风格卡 | 存在即优先（用户已认可的口径） |
| L2 自学习共识版 | `~/.dsh/template-library/<类别>/共识-骨架.md` + `共识-风格卡.md` | 用户历史模板满 3 份后交叉提炼的共识 | L1 无此主题时 |
| L3 内置出厂版 | preset `assets/templates/` | 随包内置 11 类骨架+风格卡 | L1/L2 均无时兜底 |

查找顺序固定为 **L1 → L2 → L3**；L3 也没有该类别时，先问用户有无参考模板（有则走路径 A 并登记新类别），没有则按 persona 通用大纲撰写并说明。

## 何时使用

- 用户传入模板全文（对话粘贴）或模板文件（.md / .docx / .txt / PDF，先 read 或可视化读取），并要求按模板完成新文书时（路径 A）。
- 用户说"按这个格式写"、"模仿这份文档"、"学一下它的思路"、"照它的风格来"时（路径 A）。
- 用户直接要求写某类文书但**没有给模板**时（路径 B，按三层知识库选模板）。
- 模板可以是文档正文，也可以是几篇同类文档（多篇时先交叉提炼共性，再写）。

## 路径 A：用户传了模板（现场学习 + 存档）

### A1. 接收并读取模板
- 对话粘贴：直接使用。
- 文件路径：用 read 读取（.docx/.pdf 先转文本或可视化提取）；读取失败就向用户要文本。
- 多份模板：合并拆解，标注各模板共有的骨架与各自特色，取共性为主、特色为辅。

### A2. 四维拆解（核心步骤）
逐维分析，把发现**写进笔记**（可用 todo 或草稿文件，最终汇入骨架与风格卡）：

**① 结构（骨架）**：章节层级树（几级标题、每节的标题命名规律）、章节顺序与组织逻辑（总-分-总？问题→方案→验证？时间线？）、每节大致篇幅与段落节奏。

**② 思路（逻辑）**：信息编排顺序（先结论后细节，还是先铺垫后揭晓）、每节回答什么问题、论证/叙述方式（数据驱动？案例驱动？对比？）、例证与数据放在什么位置、如何做过渡。

**③ 语言（风格）**：语气（正式/中性/亲切）、人称（我们/你/无主语）、术语使用（专有名词、中英混用习惯）、句式习惯（长句/短句、主动/被动）、标点与数字规范、**引号规范（默认中文引号“”，结合上下文：文档主体为英文时用英文引号 "，中文语境中引用英文原文可保留英文引号；代码块内保持原样）**、避免 AI 味（可调用 humanizer-zh / remove-ai-flavor / stop-slop 自查）。

**④ 格式（排版）**：标题层级与编号方式（1.1/1.1.1、一/（一））、列表/表格的使用场景、代码块标注与命令呈现方式（是否带提示符、注释语言）、加粗/斜体/引用块用法、图表与目录习惯、页眉页脚或落款等附加要素。

### A3. 产出「骨架 + 风格卡」并持久化（两处落盘）
把拆解结果整理成两个文件：

1. **工作区** `docs/style-cards/`（项目级确认口径）：文件按模板主题命名，如 `docs/style-cards/使用说明书-骨架.md`、`docs/style-cards/使用说明书-风格卡.md`。
   - 骨架文件：章节树（含层级与标题命名）+ 每节要点（该节回答的问题、必备内容、篇幅提示）。
   - 风格卡文件：语言规范（语气/人称/术语表/句式/数字标点/引号规范）、格式规范（编号/表格/代码块/强调用法）、思路特征（编排顺序/论证方式/过渡手法）、避免事项。
2. **自学习模板库** `~/.dsh/template-library/`：把模板原文（或提取的正文）存档到对应类别目录，命名 `<YYYY-MM-DD>-<NN>-<简述>.md`，并同步维护 `INDEX.md`（份数、共识版状态）。类别不存在则新建目录并在 INDEX 登记。

写完后向用户简要报告学到的要点（一两句即可），并说明已保存的位置。

### A4. 自学习提炼（模板库满 3 份自动执行）
存档后检查该类别模板份数：
- 份数 **≥ 3**：交叉提炼全部存档模板的共性，生成/更新 `共识-骨架.md` 与 `共识-风格卡.md`（结构共性为主、特色标注为辅），并更新 INDEX；
- 份数 **> 10**：删除最旧一份（按文件名日期排序），更新 INDEX；
- 每次新存档后重新提炼（共识随样本增长而演进）。

### A5. 按骨架与风格卡撰写
- **大纲 gate（硬性）**：先按骨架列出新文书大纲，**必须与用户确认后才写正文**（确认方式：直接给出大纲等用户点头，或用 ask_user_question）；未经确认不得动笔，用户仅要求调研/盘点/核对时除外。
- 撰写时严格对齐：骨架（章节不缺、顺序不乱）、思路（编排逻辑与模板一致）、语言（语气/术语/句式照风格卡）、格式（编号/表格/代码块照风格卡）。
- 引号：默认中文引号“ ”，结合上下文（英文文档/英文原文引用用英文引号）。
- 内容永远来自真实调研（项目代码、配置、命令），模板只提供形式与思路，**严禁把模板里的具体数据、版本号、项目名照抄进新文档**。

### A6. 对照自检（交付前必做）
逐项对照模板检查新文档：
- 结构完整：骨架每个章节都写了，层级与标题命名一致？
- 思路一致：信息编排顺序、论证方式符合模板逻辑？
- 语言一致：语气、人称、术语、句式与风格卡相符？无 AI 味？
- 格式一致：编号、表格、代码块、强调用法与模板排版相符？
- 内容真实：无照抄模板数据、无编造细节、命令可执行？
- 引号检查：引号风格与文档语言一致（中文文档无英文双引号，英文文档用英文引号）。
- 截图检查：文档引用截图已用 OCR/视觉工具核实过内容（无 loading/空白/错误画面）。
- 错别字与标点：终检一遍。

自检发现问题就地修改；交付时若尚未询问过，主动问用户是否需要去 AI 味（确认后按 tech-doc-deai 执行）。

## 路径 B：用户没传模板（从知识库选模板）

1. 判断文档类别（使用说明书 / 开发概要说明书 / 汇报总结材料 / 接口文档 / 技术评审稿 / 需求规格说明书 / 项目计划书 / 测试报告 / 部署运维手册 / 周报会议纪要 / 软著申请说明书 / 其他）。
2. 按 **L1 → L2 → L3** 查找该类别的骨架与风格卡：
   - L1：工作区 `docs/style-cards/` 有同主题文件 → 优先用（用户确认过的口径）；
   - L2：`~/.dsh/template-library/<类别>/` 有 `共识-骨架.md`/`共识-风格卡.md` → 用共识版；
   - L3：preset `assets/templates/` 有对应类别 → 用内置版；
   - 都没有 → 问用户有无参考模板；没有则按 persona 通用大纲撰写并告知。
3. 向用户说明"本次按 XX 模板撰写"（说明来源层级：内置/共识/工作区）；用户中途给模板则切换为路径 A。
4. 其余流程与路径 A 一致：大纲 gate → 调研 → 撰写 → 自检 → 去 AI 味询问。

## 原则

- 模板是"形式和思路的范本"，不是"内容的复制源"。
- 学习产物分两层：工作区 style-cards 是项目级确认口径；`~/.dsh/template-library/` 是用户级自学习资产（跨项目复用），共识版随样本增长自动演进。
- 用户明确传了新模板时，以新模板为准重新拆解，并照常存档（推动共识演进）。
- 模板意图不明（章节要删/要加、语气要变）时，先问清楚再动笔，不猜。
