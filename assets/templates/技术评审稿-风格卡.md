# 内置风格卡：技术评审稿

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。

## 语言规范

- **语气**：正式、中性、工程师口吻；无情感化修辞，无感叹号。
- **人称**：无主语或"本方案/该引擎/平台"；不用"我们/你们"。
- **术语**：中英混用，专有名词保留英文（Dijkstra、IoU、SLO、p95）；缩写前后一致。
- **句式**：短句为主，陈述句；结论用"是/为/采用"直陈；动作用具体动词（接入、预计算、吸附、复用）。
- **数字**：精确到有效位（45,223 节点 / 2.40 MB / ≤30ms）；千分位逗号；范围用 ~ 或 ≤。
- **强调**：**加粗** 用于关键结论、版本修订标记、需决策者注意的词；不用斜体。
- **引号**：默认中文引号“ ”，结合上下文（英文文档/英文原文引用用英文引号）。
- **版本标注**：修订处显式写「（vX.X 新增/修订/实测复核）」+ 日期。

## 格式规范

- **标题**：# 大标题（含版本号）；## 编号章节（N. 名称）；### 编号小节（N.N 名称）。
- **元信息块**：文件头部 `> **项目**：…` 引用块（项目/定位/状态/日期/版本/来源）。
- **结论块**：`>` 引用块放核心结论、评审决策、警示；✅ 标记已确认项。
- **表格**：分层表、对比表、清单表；对齐列用 `|---:|`。
- **列表**：要点用 `-`；顺序步骤用 `1.` 编号。
- **分隔**：章节之间用 `---` 水平线。
- **链接**：引用文档用相对路径 + 反引号；引用章节用 `§N.N`。

## 思路特征

- 先结论后细节：只看决策摘要即可知道答案。
- 每个论断都要有数据支撑；无数据的论断标注为"待确认"。
- 诚实标注边界：明确"不保证/不宣称等价/降级模式"。
- 保留决策轨迹：修订历史、实测复核、评审意见编号。
- 篇幅按章节重要度分配：摘要与方案设计最厚。

## 避免事项

- 无空话段（"具有重要意义""值得关注"类句子一律不出现）。
- 不用"首先/其次/最后"转场；用编号章节推进。
- 不用口语词；不堆砌排比；不写"综上所述"——直接给结论。
- 数字不给虚数（"大幅提升" → 必须带具体数值）。
- 不编造测试数据、性能数字、版本信息。

## 结构红线（对照自检）

1. 决策摘要含建议结论/核心架构/关键收益/上线门槛；
2. 有范围与非目标（明确不保证项）；
3. 方案设计含对比论证与参数范围；
4. 有性能 SLO、验证方案、测试清单、灰度路线；
5. 风险/待确认/定稿条件/版本记录齐全；
6. 图/表编号连续，正文先引用；引号风格与文档语言一致。
