# 内置风格卡：测试报告

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。

## 语言规范

- **语气**：客观、实证；结论只描述事实与数据，不辩解不夸大。
- **人称**：无主语或角色名（测试人员/开发人员）。
- **句式**：短句 + 陈述；缺陷描述用"步骤/期望/实际"三段式。
- **术语**：缺陷级别、用例编号、需求编号全文统一。
- **数字**：一切统计精确（数量、通过率、耗时）；百分比给基数。
- **引号**：默认中文引号“ ”，结合上下文（英文文档/英文原文引用用英文引号）。

## 格式规范

- **标题编号**：阿拉伯数字"1. / 1.1."。
- **表格**：环境表、执行统计表、缺陷统计表、遗留缺陷表、性能对比表——表格是主力表达。
- **编号**：用例 TC-xx、缺陷 BUG-xx，与需求 FR-xx 对应。
- **强调**：**加粗** 用于结论与严重级别；`> ⚠️` 用于遗留风险提醒。
- **代码块**：复现命令、日志片段标注语言。

## 思路特征

- **编排顺序**：结论摘要先行（通过与否 + 关键数字）→ 环境 → 执行 → 缺陷 → 专项 → 回归 → 结论。
- **用例套路**：编号 → 前置条件 → 步骤 → 期望结果 → 实际结果 → 结论。
- **论证方式**：覆盖矩阵证明"测了什么"，缺陷清单证明"还剩什么"，验收对照证明"能不能上"。

## 避免事项

- 不写"测试充分、质量良好"类空洞结论；用通过率与遗留缺陷说话。
- 不隐瞒失败/阻塞用例；必须列出。
- 缺陷不写"大概/可能"；无法确认根因的标注为待排查。
- 不编造测试数据、通过率、性能数值。
- 未回归项必须说明原因，不得默认覆盖。

## 结构红线（对照自检）

1. 结论摘要含通过/失败数字与总体判断；
2. 执行统计与用例清单一致（计划/执行/通过/失败/阻塞）；
3. 遗留缺陷逐条有影响分析与处理建议；
4. 性能测试给出目标值 vs 实测值；
5. 结论对照验收标准逐项；
6. 引号风格与文档语言一致。
