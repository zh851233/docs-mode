# 内置风格卡：部署运维手册

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。

## 语言规范

- **语气**：指令式、精确；面向执行者，一句话一个动作。
- **人称**：无主语祈使（"执行……""确认……"）。
- **句式**：短句；操作步骤动词开头。
- **术语**：组件名、路径、命令与真实环境一致；端口、版本精确。
- **数字**：阈值、超时、资源规格量化；禁止"适当/尽量"。
- **引号**：默认中文引号“ ”，结合上下文；命令与代码块内保持英文符号原样。

## 格式规范

- **标题编号**：阿拉伯数字"1. / 1.1."。
- **代码块**：命令标注 shell/bash 与前置条件；敏感值用 `<占位符>`；输出示例可注释关键行。
- **表格**：端口表、依赖表、配置项表、故障表——表格是主力表达。
- **强调**：**加粗** 用于危险操作与重要提醒；`> ⚠️ 注意：` 用于破坏性操作、备份提醒。
- **列表**：安装/升级步骤用编号，严格按顺序。

## 思路特征

- **编排顺序**：环境 → 安装 → 配置 → 日常 → 升级回滚 → 故障，按生命周期推进。
- **操作套路**：每步 = 命令 + 预期结果/验证方式（"执行后应看到……"）。
- **故障套路**：现象 → 原因 → 排查 → 解决，一条故障一个表格行。

## 避免事项

- 不写"按需配置""视情况而定"类模糊指令。
- 不出现真实密码、token、密钥（一律占位符）。
- 不遗漏回滚方案（有升级必须有回滚）。
- 命令不给上下文（环境变量、工作目录）= 不可执行，不允许。
- 不编造端口、路径、版本号——无法核实的用占位并说明。

## 结构红线（对照自检）

1. 端口与目录有速查表；
2. 安装步骤全部可复制执行且每步有验证；
3. 配置项表含修改影响（重启/热加载）；
4. 有备份恢复 + 升级回滚完整步骤；
5. 故障表覆盖启动失败、连接失败、性能劣化等高频场景；
6. 全文无真实敏感信息；引号风格与文档语言一致。
