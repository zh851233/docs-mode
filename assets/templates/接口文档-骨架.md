# 内置骨架：接口/API 文档

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。
> 适用：REST/HTTP 接口文档、OpenAPI 风格描述，面向对接开发者。

## 文档整体组织

- 标题：`# XX系统接口文档（版本）`
- 元信息块：接口版本 / 更新时间 / 联系人 / 服务地址（Base URL）。
- 正文按接口分组组织，先总览后细节。

## 章节树

### 1. 接口总览
- 1.1 接口清单表：接口名称 | 方法 | 路径 | 用途 | 是否需要认证（一表览全）。
- 1.2 通用约定：Base URL、数据格式（JSON）、编码（UTF-8）、时间格式、分页约定、幂等性等。

### 2. 认证方式
- 2.1 认证机制说明（Token / API Key / OAuth 等）：获取方式、有效期、刷新方式。
- 2.2 认证示例：请求头写法（`Authorization: Bearer <token>`），明文不落盘。

### 3. 接口详情（正文主体，每个接口一节）
每个接口按固定结构：
- **接口说明**：一句话用途 + 调用场景。
- **请求**：
  - 方法 + 路径（含路径参数，如 `GET /users/{id}`）
  - 请求参数表：参数名 | 位置（path/query/header/body）| 类型 | 必填 | 说明 | 示例
- **响应**：
  - 成功响应示例（JSON 代码块，字段注释关键项）
  - 响应字段说明表（字段 | 类型 | 说明）
- **错误码**：该接口可能返回的错误码表（错误码 | HTTP 状态 | 含义 | 处理建议）。
- **调用示例**：curl 或代码片段（语言标注），命令可复制。

### 4. 错误码总表
- 全局错误码表：错误码 | 含义 | 通用处理建议。

### 5. 调用示例（可选）
- 典型业务流程的串联示例（登录 → 查询 → 操作 → 登出）。

## 每节篇幅与节奏

| 章节 | 约占篇幅 | 内容密度 |
|---|---|---|
| 接口总览 | 1~2页 | 清单表 + 通用约定 |
| 认证方式 | 0.5~1页 | 简洁，示例必须真实 |
| 接口详情 | 70%以上 | 每接口一节的固定结构 |
| 错误码/示例 | 10~15% | 表格 + 代码块 |

## 关键规范

- 参数表、字段表、错误码表是主力表达，文字只做补充。
- 每个接口必须给"请求示例 + 响应示例 + 错误码"，三件套缺一不可。
- 示例中的 token、密钥一律用占位符（`<token>`），绝不出现真实凭据。
