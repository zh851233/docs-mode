# 内置骨架：系统开发概要说明书

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。
> 适用：软件产品/系统开发概要说明书（软件概要设计说明书），面向设计与开发人员。

## 文档整体组织

- 封面页：居中大标题（系统完整名称）。
- 目录页：点线式带页码，正文重新从第 1 页编号。
- 页眉：每页顶部居中显示系统名称；页脚右下角页码。
- 图编号、表编号贯穿全文连续递增。

## 章节树（软著申报主流结构）

### 1. 引言
- 1.1 项目背景：行业/政策/痛点背景（可引用真实数据与来源）→ 技术发展背景 → 结尾固定列出软著五要素：软件的系统名称 / 本项目的提出者 / 任务开发者 / 用户 / 架构（BS/CS）。
- 1.2 编写目的：分点列出（（1）明确说明系统各功能的实现方式；（2）明确数据需求与数据格式；（3）确定功能组成模块；（4）确定各模块的功能和接口；（5）供程序设计人员阅读）。
- 1.3 参考资料：真实书籍/标准/官方文档清单。

### 2. 总体设计
- 2.1 概述：功能描述总述段 + "表1 功能描述表"（模块名称 | 功能要点 | 关键需求）。
- 2.2 运行环境：2.2.1 硬件环境（表2）、2.2.2 软件环境（表3）。
- 2.3 数据设计（如项目无数据库，如实改写为"数据设计/数据资产"）：核心数据资产表（资产文件 | 内容 | 规模 | 质量等级），含口径说明（REAL=真实数据 / ESTIMATED=模型估算 / PROXY=代理口径）、坐标口径等。

### 3. 系统架构
- 3.1 架构图：分层结构图（数据层/引擎层/计算层/展示层等，按项目实际）+ 一段架构说明。
- 3.2 功能模块：按模块分节（3.2.1…），每节一段功能叙述（该模块做什么、关键规则、交互链路）+ 图（模块图/用例图/数据流图）。

### 4. 核心功能（可选章节，深入讲 1~2 个关键实现）
- 按关键技术点分节：功能（做什么）→ 实现原理（怎么做）→ 应用场景 → 意义/效果，四段式。

### 5. 系统出错处理
- 5.1 出错信息：错误码体系与前端提示策略。
- 5.2 补救措施：分层处理（数据校验类/运行时异常/操作流程异常/系统性未知异常，分点）。
- 5.3 软件的维护：架构下的维护与扩展策略、构建管线、测试体系。

## 每节篇幅与节奏

| 章节 | 约占篇幅 | 内容密度 |
|---|---|---|
| 引言 | 1~2页 | 背景可引数据，编写目的分点 |
| 总体设计 | 4~6页 | 功能描述表 + 环境表 + 数据设计为主 |
| 系统架构 | 5~8页 | 架构图 + 每模块一段 + 图 |
| 核心功能/出错处理 | 2~4页 | 技术细节为主，文字密度高 |

## 图、表编号规则

- 图编号贯穿全文：图1、图2、图3……（图注在图下方，正文先引用）。
- 表编号独立：表1 功能描述表、表2 硬件环境、表3 软件环境、表4 数据资产（表题在表格上方）。
- 正文引用方式："如图 N 所示"、"如表 N 所示"。
