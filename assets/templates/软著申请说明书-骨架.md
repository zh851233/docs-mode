# 内置骨架：软著申请说明书

> 用途：无用户模板时的默认模板之一（用户传入模板时以用户模板为准）。
> 适用：软件著作权申请配套文档——《软件使用说明书》与《软件概要设计说明书》（开发概要说明书），面向软著审查与配套材料完整性。

## 文档整体组织

- 封面页：居中大标题（系统完整名称）。
- 目录页：点线式带页码，正文重新从第 1 页编号。
- 页眉：每页顶部居中显示系统名称；页脚右下角页码。
- 图编号、表编号贯穿全文连续递增。

## 配套文档一：系统使用说明书

### 章节树
1. 引言：1.1 编写目的 / 1.2 使用对象 / 1.3 参考资料。
2. 总体设计：2.1 功能描述（总述 + 表1 功能描述表：模块名称|功能要点|关键需求）/ 2.2 系统总体结构框架（架构图 + 数据流程图）。
3. 运行环境：3.1 硬件环境（表2）/ 3.2 软件环境（表3）。
4. 系统功能界面设计（正文主体）：按模块分节，每节 = 操作场景描述 + 真实界面截图 + 操作步骤；图随文走。

## 配套文档二：系统开发概要说明书

### 章节树
1. 引言：1.1 项目背景（政策/市场/技术背景 + 软著五要素：系统名称/提出者/任务开发者/用户/架构）/ 1.2 编写目的（分点）/ 1.3 参考资料。
2. 总体设计：2.1 概述（功能描述表，与使用说明书共用同一张表）/ 2.2 运行环境（硬件/软件）/ 2.3 数据设计（无数据库时如实改写为数据资产，含质量等级与口径）。
3. 系统架构：3.1 架构图 / 3.2 功能模块（每模块一段 + 图）。
4. 核心功能（可选）：1~2 个关键技术点，功能/实现原理/应用场景/意义四段式。
5. 系统出错处理：5.1 出错信息 / 5.2 补救措施 / 5.3 软件的维护。

## 关键规范

- **配套一致性**：两份文档共用同一张功能描述表，术语、模块名、版本号口径一致。
- **真实性与如实标注**：界面截图必须真实（无示意图）；无法核实的信息（提出者/开发者、硬件配置）用「XX（待补充）」占位；无数据库的项目不硬编"数据库设计"，如实写数据资产与数据管线。
- **质量等级**：数据口径可标注 REAL（真实）/ ESTIMATED（估算）/ PROXY（代理），体现严谨。
- 参考资料用真实文献/官方文档，不编造。
