# Built-in Skeleton: English Technical Document (Generic)

> Purpose: default template for English technical writing when no user template exists.
> Applies to: English tech docs — README, spec, manual, API doc, report. Pairs with the corresponding Chinese skeleton's chapter structure.

## Language Norms (English)

- **Tone**: neutral, direct, professional; no emotional phrasing, no exclamation marks.
- **Voice**: active voice preferred; imperative for instructions ("Run `npm install`"); third person for descriptions ("The module processes…").
- **Sentences**: short and declarative; one idea per sentence; avoid stacking subordinate clauses.
- **Terms**: keep technical terms in English as-is (API, Docker, JSON, H3); define acronyms on first use ("Location Based Service (LBS)").
- **Numbers**: precise and unit-quantified ("p95 ≤ 300ms", "45,223 nodes"); no vague "fast/significant/many".
- **Quotes**: English quotes " " in English context; keep original quotes when citing another language.

## Chapter Structure (adapt per document type)

1. **Overview / Abstract**: what the document covers, key conclusion first.
2. **Background & Goals**: problem statement, success criteria.
3. **Scope**: in scope / out of scope (explicit exclusions).
4. **Design / Implementation** (per module): purpose → approach → parameters → trade-offs.
5. **Data / Interfaces** (if applicable): data model, API endpoints, schemas.
6. **Environment & Dependencies**: versions table, runtime requirements.
7. **Usage / Operation**: step-by-step with copy-paste commands.
8. **Verification / Testing**: test matrix, acceptance criteria.
9. **Risks & Limitations**: honest boundaries ("does not guarantee…").
10. **Appendix**: glossary, reference links, version history.

## Format Norms

- Headings: `# Title`, `## 1. Section`, `### 1.1 Subsection` (numbered, dot after number).
- Tables for parameters, versions, comparisons; code blocks labeled with language.
- Bold for key conclusions; `> Note:` blockquotes for warnings.
- Figure/table numbering continuous ("Figure 1", "Table 2"), referenced before appearing.

## Red Lines (self-check)

- [ ] Numbers and versions are real and consistent across docs.
- [ ] Commands are copy-paste executable with environment noted.
- [ ] English quotes " " used in English context (no Chinese quotes).
- [ ] No AI-flavor filler ("It is worth noting that…", "delve into", "seamless", "empower").
- [ ] Every claim is backed by data or explicitly marked as assumption.
